# Leads — customers from Google ads, paid per lead (2026-11-15)

Owner's brief (15 Nov): connect the owner's Google Business Profile in the app; we run ads on their listing
from an ad account only we control, with our number on the ad; a caller is a lead; we qualify it and send it
to the owner "like Uber shows a ride"; the owner pays per lead (our cost + ₹10), on the spot or from a wallet;
the number shows once paid. Spec: `docs/specs/leads.md`.

## What shipped (built and deployed 15 Nov 2026 — server 2aa30ef, GitHub main synced)

- **Backend** (courses branch `leads`): tables `laundry_leads`, `laundry_wallets`, `laundry_wallet_txns`,
  `laundry_wallet_orders`, `laundry_gbp_connections`, `laundry_devices` (migration `20261115120000_laundry_leads`);
  `/api/laundry/leads` (owner + `/admin/*` with `X-Admin-Key` = `LAUNDRY_LEADS_ADMIN_KEY` else `LAUNDRY_AI_CALL_KEY`),
  `/api/laundry/devices`; `experiments.leads`; the Razorpay webhook credits wallet orders (`notes.kind = laundry_wallet`);
  sweeps expire leads every minute and reconcile unreported wallet orders every 3 min. 66 unit tests pass; the whole
  owner + admin flow was exercised against a throwaway Postgres (`scratchpad/smoke.sh`).
- **Android 1.0.22** (prod branch): Settings → Get customers (when `experiments.leads`), the Leads screen (wallet,
  Google connection or Maps link, waiting / paid / earlier leads), the pay sheet (wallet → pay now → add money & pay),
  the Home "new customer waiting" card, push channel `leads`, deep links `mylaundry://leads` and `mylaundry://lead/<id>`,
  FCM token registration (`data/leads/DeviceRegistrar`), Razorpay Orders through the shared `CheckoutBridge`.
- **admin.mylaundry.work**: `/leads` (tiles, Send-a-lead form with the caller picked from recent incoming Vobiz calls,
  table with cancel / refund / re-offer / push again), `/leads/connections`, and "Leads & wallet" on the owner panel.

## Deploy

```sh
courses/deploy/2026-11-15-leads.sh --dry-run
courses/deploy/2026-11-15-leads.sh            # migrate, env, rebuild backend, patch + restart laundry-dash, smoke
```

The script starts the feature for the owner's own numbers only (`LEADS_PHONES=…` env of the script); set
`LAUNDRY_LEADS_PHONES=all` in `backend/.env` and recreate the backend to show it to everyone. The app release
(1.0.22 AAB) is the owner's build as usual.

## The owner's Google steps (only you can do these)

1. **OAuth client (Web application)** in the Google Cloud project behind Firebase `shweta-makeover`:
   APIs & Services → Credentials → Create credentials → OAuth client ID → Web application. Put its id and
   secret in `backend/.env` as `LAUNDRY_GOOGLE_OAUTH_CLIENT_ID` / `LAUNDRY_GOOGLE_OAUTH_CLIENT_SECRET`, recreate the
   backend. The app shows **Connect with Google** only when the server has them; before that owners paste a Maps link.
2. **OAuth client (Android)** in the same project: package `com.dailyworks.apnalaundry`, the release SHA-1 (Play
   App Signing certificate) and the debug SHA-1. Without it Google refuses the app's sign-in.
3. **OAuth consent screen**: add the scope `https://www.googleapis.com/auth/business.manage`. While the app is in
   "Testing", only listed test accounts can connect; publish it (verification) for every owner.
4. **Business Profile API access**: enable the Business Profile APIs and request access
   (https://developers.google.com/my-business/content/prereqs). Until approved, a connection stores the Google
   account and `apiError`; locations load after approval (the "Refresh from Google" button on `/leads/connections`).
5. **Google Ads**: link your Ads account to each owner's Business Profile (Ads → Linked accounts → Business
   Profile; the owner approves, or you manage their profile). Put the Vobiz number +91 92409 54178 as the ad's
   call asset so calls land in the support app (incoming calls are already live).

## Backward compatibility

- Apps before 1.0.22 ignore `experiments.leads` and never call the new routes; the website is untouched.
- The Razorpay webhook branch only runs for payments whose `notes.kind` is `laundry_wallet`; subscription events are
  processed exactly as before.
- `services/laundry-support-push.js` now sends through `services/laundry-fcm.js` — same messages, same behaviour.
- A staff token gets 403 on the new routes (owner-only), like every other owner route.

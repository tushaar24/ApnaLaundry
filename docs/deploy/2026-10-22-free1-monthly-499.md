# Every new account gets free1 at ₹499/month (2026-10-22)

**What the owner asked for:** free1 for 100% of new users, and the pricing shown when they try a 2nd order should be ₹499 Monthly only.

**Change:** `LAUNDRY_PAYWALL_CONFIG` gets a new split, starting when the script runs. The split puts 100% of new accounts in a new variant:

```json
"free1_monthly_499": { "gate": "free_orders", "plans": ["monthly"], "default": "monthly",
                       "trialDays": 0, "freeOrders": 1, "prices": { "monthly": 499 } }
```

- **1 free order.** Opening New order for a 2nd order shows the paywall: Monthly ₹499 only, charged on approval, no ₹2 trial.
- **No extra pop-up after the first order** (`free_orders` gate). The old free1's first-order paywall was closed by 33 of 35 owners and brought in no payments; both of its ₹199 payments came from the New-order wall.
- **Why the name isn't `free1`:** that is a built-in legacy group at ₹199. The server checks the legacy group before the config, so the name has to differ.
- **Accounts created before the split keep their variant.** `hard_trial_yearly_plus_monthly_4999_499` stays a login hard gate.

## Who gets what

| New account | Gets |
|---|---|
| App 1.0.13 / 1.0.14 | `free1_monthly_499` as above |
| App 1.0.12 | Legacy free1: 1 free order, ₹199/month. That app can't draw config variants |
| App 1.0.11 or older | Not in the config. It stays in the 3 vs 5 free-orders test with the standard plans |
| Website | Unchanged: the ₹2, 7-day-trial hard gate |

The script's dry run checked this against the live service code on 2026-10-22.

## Run

```sh
DRY_RUN=1 bash docs/deploy/2026-10-22-free1-monthly-499-deploy.sh   # builds and checks; changes nothing
bash docs/deploy/2026-10-22-free1-monthly-499-deploy.sh             # applies
```

The script:
1. backs up `backend/.env` to `~/backend-filebak/<ts>-free1-monthly-499/`;
2. swaps only the config line;
3. recreates the backend;
4. rolls back automatically if the backend logs a `[paywall]` error;
5. recreates `laundry-dash`, so admin.mylaundry.work labels the new variant.

**Rollback:**
1. Copy the backup `.env` back.
2. `docker compose -f docker-compose.prod.yml up -d --force-recreate backend`
3. `docker compose -f docker-compose.prod.yml up -d --force-recreate --no-deps laundry-dash`

Accounts created while the split was live keep `free1_monthly_499` unless the split is edited.

## Known gap (owner: leave as is): deleting orders frees the free slot

Since app 1.0.9 (8ac6fe9), the free-order limit counts only orders that aren't deleted. An owner can delete their one order and make another. On 21 Oct, 10 of 16 active free owners who don't pay had used this, one of them 25 times. The owner decided on 2026-10-22 to leave it as is.

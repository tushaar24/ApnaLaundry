# Deploy: GST on orders (2026-10-09)

Per-order GST — exclusive (added on top) or inclusive (already in the price),
with the shop's last-used setting pre-filling every new order. Spec:
`HANDOFF-gst.md` (the Claude Design handoff), design row "GST — inclusive /
exclusive per order".

Order: **backend first** (additive — new columns have defaults, and sync/push
writes the new fields only when a client sends them, so older app builds keep
working and can't wipe them), then the website. Android ships with the next
Play build (Room schema v7, migration 6→7).

## 1. Backend (courses-aws, `~/shweta-makeup-monorepo/backend`)

`2026-10-09-backend-gst.patch` (next to this file) was diffed against the
files **as they are on the server today** (copied over scp), so it should apply
cleanly. It adds:
- migration `20261009180000_laundry_gst` — `gst_on` / `gst_pct` / `gst_mode` on
  `laundry_orders` (defaults off / 0 / excl) and on `laundry_shops` (defaults
  off / 18 / excl, the last-used setting);
- `schema.prisma` fields for both;
- sync/push: the order's GST is written **only when the client sends it**
  (same rule as `serialNo` / `exPct`); the shop defaults go through
  `laundry-shop-details.js` like the other bill details;
- the public bill (`/b/<token>`) payload gains `gstOn`, `gstPct`, `gstMode` so
  the customer's page shows the same tax lines as the app.

```bash
scp docs/deploy/2026-10-09-backend-gst.patch courses-aws:/tmp/
ssh courses-aws
cd ~/shweta-makeup-monorepo/backend
patch -p1 --dry-run < /tmp/2026-10-09-backend-gst.patch   # must apply cleanly
patch -p1 < /tmp/2026-10-09-backend-gst.patch
cd .. && docker compose -f docker-compose.prod.yml run --rm --build migrate
docker compose -f docker-compose.prod.yml up -d --build backend
git add backend/prisma backend/routes/laundry.js \
        backend/services/laundry-bill-links.js backend/services/laundry-shop-details.js
git commit -m "feat(laundry): GST per order (gst_on, gst_pct, gst_mode) + shop defaults"
```

## 2. Website (from branch `prod`, after merging `feat/gst-on-orders`)

Dry-run first, then sync `web/` (keep the server-only `.env`, `node_modules`):

```bash
git archive prod web | tar -x -C /tmp/web-prod
rsync -rcn -i --exclude node_modules --exclude .next /tmp/web-prod/web/ courses-aws:apnalaundry-web/
# check only intended files differ, then rerun without -n, and:
ssh courses-aws 'cd ~/shweta-makeup-monorepo && docker compose -f docker-compose.prod.yml up -d --build laundry'
```

## 3. Android

Nothing to deploy by hand — the next Play build carries the Room 6→7 migration
and the new sync fields. Until it ships, old app builds send orders without
GST fields and the server keeps whatever the web saved.

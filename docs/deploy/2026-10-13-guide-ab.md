# Deploy: guide A/B test — `GET /api/laundry/experiments` (2026-10-13)

The Android guide (step-by-step walkthrough with voice, `ui/tour/`, app 1.0.10)
runs as a 50/50 A/B test decided by the backend, so the split can change
without an app release.

- **Route** `routes/laundry-experiments.js`, mounted in `app.js` at
  `/api/laundry/experiments` (logged-in, before the generic `/api/laundry`
  router): `GET /` → `{ success, experiments: { guide: "guide" | "no_guide" } }`.
- **Split**: bucket = sha256(`guide_v1:<userId>`) % 100 — stable per shop;
  `guide` when bucket < `LAUNDRY_GUIDE_PCT` (backend `.env`, default **50**).
  Raising it only moves `no_guide` shops into `guide`; `0` = nobody, `100` =
  everyone (then rebuild/restart the backend). Changing `guide_v1` re-buckets
  everyone — only for a fresh test.
- **CleverTap**: the server sets profile property `Guide_Variant` (`guide` /
  `no_guide`) on the first call per user after each restart; the app sets the
  same property. Split any funnel (Order Saved, Order Delivered, orders_count,
  Paywall Shown …) by it; the guide's own funnel is the `Tour *` events.
- **App**: fetches its group at app start and right after login (while setup
  runs), saves it; `guide` = the guide auto-starts for a shop with no orders
  and Settings shows "How to use the app"; `no_guide` (or not fetched yet, or
  an old backend) = neither. Support contact in Settings is for everyone.
- No migration, no schema change.

## Apply on courses-aws

From the app repo root (backs up `app.js`, dry-runs, patches, syntax-checks,
commits on the server's `main`, rebuilds the backend in the background):

```sh
ssh courses-aws 'set -e
cd ~/shweta-makeup-monorepo/backend
B=~/backend-filebak/$(date -u +%Y%m%d-%H%M%S); mkdir -p $B; cp -a app.js $B/
cat > /tmp/guide-ab.patch
patch -p1 --dry-run < /tmp/guide-ab.patch && patch -p1 < /tmp/guide-ab.patch
docker run --rm -v $PWD:/x shweta-makeup-monorepo-backend node --check /x/routes/laundry-experiments.js
docker run --rm -v $PWD:/x shweta-makeup-monorepo-backend node --check /x/app.js
cd .. && git add backend/app.js backend/routes/laundry-experiments.js && git commit -q -m "laundry: guide A/B test endpoint (GET /api/laundry/experiments)"
nohup docker compose -f docker-compose.prod.yml up -d --build backend > /tmp/backend-build.log 2>&1 &
echo started' < docs/deploy/2026-10-13-backend-guide-ab.patch
```

Then wait for the container to be recreated
(`docker inspect -f {{.Created}} $(docker compose -f docker-compose.prod.yml ps -q backend)`)
and check `GET /api/laundry/experiments` with a logged-in token returns the group.

Roll back: restore `app.js` from the backup folder, remove
`routes/laundry-experiments.js`, rebuild the backend. The app then treats every
shop as `no_guide`.

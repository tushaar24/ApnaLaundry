# App languages (Android)

The app speaks English + 10 Indian languages (Hindi, Marathi, Gujarati, Bengali, Tamil, Telugu, Kannada, Malayalam, Punjabi, Odia).
- **Where it's chosen:**
  - a picker that opens with the login screen every time (it can't be skipped the very first time);
  - the chip at the top right of login;
  - Settings → Language.
- **Where it's kept:** on the phone, not on the account.
- **Code:** `core/I18n.kt`.

## How text is written

Screen text stays in English in the code, wrapped in `tr(…)`:

```kotlin
import com.dailyworks.apnalaundry.core.tr

Text(tr("Mark ready"))
CmdResult(tr("Picked up · {name}", "name" to nm), undo)
Text(tr("{n} orders", "n" to list.size))
```

**Rules:**
1. **Every text a person reads goes through `tr`:**
   - `Text`, button labels, placeholders, titles;
   - toasts and errors shown on screen, dialogs;
   - `contentDescription`;
   - WhatsApp message texts.
2. **The first argument is one plain string literal**, no `$` templates and no `+` inside the call. Dynamic parts are **named** placeholders (`{name}`, `{n}`, `{amount}`, `{shop}`, `{date}`…) passed as `"key" to value`.
   - Names tell the translator what goes there.
   - Format values first: `"amount" to Money.rupees(x)`.
3. **Whole sentences, not fragments.** If a sentence changes with a condition, write each full variant: `if (paid) tr("Paid") else tr("{amount} due", …)`.
4. **Plurals:** keep the existing check, with both forms wrapped: `if (n == 1) tr("{n} item", "n" to n) else tr("{n} items", "n" to n)`.
5. **Evaluate `tr` when the text is shown.** Do it inside a function, a getter or a composable, never in a top-level / `object` `val` initializer: the language can change while the app runs. Turn `val x = Thing(tr("…"))` in an object into `val x get() = Thing(tr("…"))` or a function.
6. **Text defined in one place and shown elsewhere:**
   - enum labels: keep the English constant;
   - mark it where defined with `i18n("Orders")` so the catalogue tool finds it;
   - show it with `tr(label)`.
7. **Never translate:**
   - analytics event names and properties, log text, JSON / prefs / route keys, enum names;
   - data people typed or the app stores (customer, service and item names; default rate-card names in `SeedData`);
   - `₹` amounts (use `Money`);
   - text sent to the assistant model (`AssistantTools` results, the system prompt).
8. **The bill document stays English** (it matches the bill's web page). Build receipts inside `I18n.english { … }` so the dates and labels it borrows (`AppDate`, `Selectors`) come out in English. Printed tags stay English: thermal printers can't draw Indian scripts.

## Catalogues

`app/src/main/assets/i18n/<code>.json` holds one map per language: English text → translation.
- They are made from the code by `tools/i18n/translate.py`, which collects every `tr("…")` / `i18n("…")` literal and translates the new ones with Sarvam AI (`sarvam-105b-conversations`).
- A translation that loses or changes a placeholder is dropped, and that text shows in English.

```sh
SARVAM_API_KEY=… python3 tools/i18n/translate.py          # adds missing translations
SARVAM_API_KEY=… python3 tools/i18n/translate.py --check  # lists tr() problems, translates nothing
```

Run it after adding or changing screen text. A text without a translation shows in English until then.

**Hand corrections:** put them in `tools/i18n/overrides.json` (language → English → translation). They win on every run. Use them for one-word buttons that came out as a noun, e.g. Hindi "Change" → "बदलें", not "बदलाव".
